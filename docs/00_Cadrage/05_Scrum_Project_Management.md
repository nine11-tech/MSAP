# Gestion Scrum Adaptee - MSAP

## Adaptation Scrum pour PFA Solo

MSAP est gere comme un projet Scrum simplifie. L'etudiant assume le role principal de developpement et de pilotage, avec validation periodique par les encadrants.

## Roles

- **Product Owner**: represente le besoin academique et cybersécurité; role partage entre etudiant et encadrant.
- **Scrum Master**: l'etudiant organise le suivi, les blocages et la discipline de sprint.
- **Development Role**: l'etudiant realise conception, documentation, implementation, tests et demo.

## Sprint Length

Chaque sprint dure 1 semaine, aligne avec la roadmap 8 semaines.

## Ceremonies

### Sprint Planning

Definir objectif de sprint, user stories, taches techniques, livrables et criteres d'acceptation.

### Daily Self-Check

Revue courte quotidienne:

- Qu'ai-je termine ?
- Qu'est-ce qui bloque ?
- Quel livrable dois-je produire aujourd'hui ?

### Sprint Review

Presenter les livrables: document, diagramme, fonctionnalite, test ou demo partielle.

### Sprint Retrospective

Identifier ce qui a bien fonctionne, ce qui doit etre ajuste et les risques restants.

## Product Backlog Management

Le backlog regroupe epics, features, user stories, exigences de securite et livrables.

## Sprint Backlog

Chaque sprint extrait un sous-ensemble realiste du product backlog, priorise par valeur PFA et dependances techniques.

## Definition of Ready

Une tache est prete si:

- son objectif est clair;
- les entrees necessaires sont disponibles;
- les criteres d'acceptation sont definis;
- le perimetre reste compatible V1.

## Definition of Done

Une tache est terminee si:

- le livrable est cree ou implemente;
- il est coherent avec MASVS + ATT&CK;
- il respecte les contraintes local-first;
- il est verifie ou relu;
- la documentation est mise a jour si necessaire.

## Sprint Review Deliverables

- Documents valides.
- Diagrammes.
- Code MVP.
- Tests.
- Rapport ou export.
- Demo partielle.

## Burndown Concept

Un burndown simple peut suivre le nombre de taches restantes par semaine. L'objectif est de detecter rapidement un perimetre trop large.

## GitHub Issues / Projects

GitHub Issues peut etre utilise pour:

- user stories;
- bugs;
- taches techniques;
- risques;
- suivi DoR/DoD;
- jalons hebdomadaires.
